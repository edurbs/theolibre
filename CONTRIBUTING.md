# Contributing to TheoLibre

Thank you for your interest in contributing to **TheoLibre**!

TheoLibre is an independent, source-available desktop application for reading and working with digital publications. It is built with Java and JavaFX.

We welcome bug reports, feature proposals, documentation improvements, translations, code contributions, testing, and other forms of noncommercial collaboration.

## What You Can Contribute

Examples of welcome contributions include:

* Bug fixes
* New features
* Performance improvements
* Refactoring
* Unit and integration tests
* JavaFX user-interface improvements
* Accessibility improvements
* Documentation
* Translations and localization
* Build and packaging improvements
* Linux integration
* Support for additional publication formats
* Improvements to `.jwpub` compatibility
* Search and indexing improvements
* Library-management features

Before starting substantial work, please consider opening an issue to discuss the proposed change.

## Noncommercial Contributions

TheoLibre accepts contributions for noncommercial purposes.

Examples include:

* Personal projects
* Hobby projects
* Academic and educational work
* Research
* Open collaboration
* Testing and experimentation
* Contributions made by charitable or other permitted noncommercial organizations

Contributions must not be made for the purpose of creating or distributing a commercial version of TheoLibre.

## Commercial Use

TheoLibre is **not licensed for commercial use**.

Without separate written permission from the applicable copyright holder, contributions must not be intended to enable or facilitate:

* Selling TheoLibre
* Selling modified versions of TheoLibre
* Commercially distributing TheoLibre or a derivative work
* Incorporating TheoLibre code into paid or commercial software
* Offering TheoLibre as part of a paid service
* Deploying TheoLibre as part of a commercial product or service
* Creating a commercial fork of TheoLibre

If you are interested in commercial use, please contact the project copyright holder before proceeding.

A separate written commercial license may be required.

## Before You Contribute

Before submitting a pull request:

1. Make sure your contribution is your own work or that you have the necessary rights to contribute it.
2. Make sure you are not knowingly submitting copyrighted material that you are not permitted to redistribute.
3. Make sure your contribution does not include proprietary source code, assets, publications, or other material belonging to third parties.
4. Run the relevant tests.
5. Verify that the project builds successfully.
6. Update documentation when necessary.
7. Keep the change focused and avoid unrelated modifications.

## Third-Party Code and Dependencies

Do not copy code from another project into TheoLibre unless its license permits the intended use and redistribution.

When adding a dependency, please verify:

* Its license
* Its compatibility with the TheoLibre license
* Its redistribution requirements
* Its attribution requirements
* Whether it introduces additional restrictions or obligations

Record new dependencies in the appropriate build configuration and documentation.

## `.jwpub` Files and Third-Party Content

TheoLibre may support opening and reading `.jwpub` files used by **JW Library®**.

Contributors must **not** submit copyrighted publications, media, images, audio, video, or other third-party content to the repository unless the project has the necessary rights to redistribute that material.

Do not include `.jwpub` publication files in pull requests unless the project explicitly requests a file that is legally redistributable.

The ability of TheoLibre to read a file format does not grant permission to redistribute the content contained in files using that format.

## Code Style

TheoLibre is a Java/JavaFX project.

When contributing code:

* Follow the existing project structure.
* Prefer clear and maintainable code over clever implementations.
* Keep classes and methods focused.
* Avoid unnecessary dependencies.
* Follow the project's existing formatting conventions.
* Add tests for new functionality where practical.
* Avoid introducing unrelated refactoring into feature or bug-fix pull requests.

## Commit Messages

Use concise and descriptive commit messages.

Examples:

```text
Add jwpub manifest parser
Fix publication search indexing
Improve library navigation
Add Portuguese localization
Fix JavaFX reader layout
```

Avoid messages such as:

```text
fix stuff
changes
update
test
```

## Pull Requests

A good pull request should:

* Have a clear title.
* Explain what problem it solves.
* Describe the approach taken.
* Include relevant tests.
* Mention any known limitations.
* Include screenshots for significant UI changes when appropriate.

Keep pull requests focused. Large changes should generally be discussed in an issue before implementation.

## Bug Reports

When reporting a bug, please provide as much relevant information as possible:

* Operating system
* Java version
* TheoLibre version or commit
* Steps to reproduce
* Expected behavior
* Actual behavior
* Relevant logs or stack traces
* Screenshots when useful

Please do not upload copyrighted publications or personal information to demonstrate a problem unless you have the necessary rights and it is appropriate to do so.

## Feature Requests

Feature requests are welcome.

Please explain:

* What problem the feature would solve
* Who would benefit from it
* How you expect it to work
* Whether it affects existing functionality

Features that significantly change the architecture should be discussed before implementation.

## Translations

Translations are welcome.

Please preserve:

* Meaning
* UI terminology
* Technical terms
* Keyboard shortcuts
* Formatting placeholders

Do not translate trademarks, product names, or technical identifiers unless the project's localization guidelines explicitly require it.

## Code of Conduct

Contributors are expected to behave respectfully and constructively.

Harassment, personal attacks, discrimination, intentional disruption, and other unacceptable behavior are not welcome in the project.

A separate [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) may provide additional details.

## Attribution

By submitting a contribution, you represent that:

1. You have the right to submit the contribution.
2. The contribution does not knowingly violate another person's copyright or other rights.
3. You understand that your contribution may be incorporated into TheoLibre and distributed under the project's applicable license.

Unless otherwise agreed, contributors retain copyright in their original contributions.

## Copyright

Copyright ownership of contributions remains with their respective authors unless a separate written agreement states otherwise.

Contributors should not add copyright notices claiming ownership of another person's work.

## Questions

If you are unsure whether a contribution is compatible with the project's license, especially regarding commercial use, third-party code, or copyrighted content, open an issue or contact the project maintainers before submitting the contribution.

When in doubt, ask first.

Thank you for helping make TheoLibre better!
